# Учебный шаблон проекта

Готовое веб-приложение для первого учебного проекта. В нём есть три независимых
раздела с полным CRUD: задачи, заметки и отчёты о настроении. Ученик запускает
проект, изучает готовый код и постепенно расширяет его под свою идею.

Стек намеренно простой:

- HTML, CSS и чистый JavaScript без фреймворков и сборщиков;
- Node.js и Express;
- SQLite через синхронную библиотеку `better-sqlite3`;
- никаких ORM, TypeScript, `async/await` на бэкенде, foreign key и JOIN.

папка `data/` с файлом базы `app.db`. Обе создаются автоматически и не входят в Git.

## Как устроен проект

Запрос проходит путь:

```text
HTML-страница → JS (fetch) → Express-маршрут → модель → SQLite
```

- **Страница** — отдельный HTML-файл. Переходы между разделами работают как обычные
  ссылки, без JavaScript-роутера.
- **api.js** — единственное место на фронтенде, где используется `fetch`.
- **Маршрут** — правило Express вида «метод + адрес». В нём находятся проверка данных
  и формирование HTTP-ответа.
- **Модель** — модуль с SQL-запросами для одной таблицы.
- **SQLite** — база данных в одном файле `data/app.db`.

Ответы API — JSON. Ошибки проверки возвращаются со статусом `400` в формате:

```json
{ "error": "Поле \"text\" не должно быть пустым" }
```

## Установка

Нужен Node.js версии 20 или новее. Проверить версию:

```bash
node --version
```

Установить зависимости:

```bash
npm install
```

`better-sqlite3` содержит нативную часть. Обычно для неё есть готовый файл, но на
некоторых системах может понадобиться Python и средства сборки C++. Если установка
не удалась, проверьте, что версия Node.js поддерживается библиотекой.

В новых версиях npm установочные скрипты пакетов могут быть заблокированы.
В `package.json` уже есть разрешение для `better-sqlite3`, но если npm всё равно
сообщает о блокировке, выполните:

```bash
npm install-scripts approve better-sqlite3
npm rebuild better-sqlite3
```

## Настройка .env

Создайте копию примера настроек:

```bash
cp .env.example .env
```

В Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

Содержимое `.env`:

```dotenv
PORT=3000
DB_PATH=data/app.db
```

- `PORT` — порт сервера. Если 3000 занят, поставьте, например, 3001.
- `DB_PATH` — путь к файлу базы относительно папки проекта.

Файл `.env` не попадает в Git. Если его нет, приложение всё равно запустится
со значениями по умолчанию (порт 3000 и `data/app.db`).

## Запуск

```bash
npm start
```

Для разработки удобнее режим с автоматическим перезапуском после изменения файлов:

```bash
npm run dev
```

После запуска откройте:

- <http://localhost:3000> — перенаправит на задачи;
- <http://localhost:3000/tasks.html>;
- <http://localhost:3000/notes.html>;
- <http://localhost:3000/reports.html>;
- <http://localhost:3000/example.html> — пример новой страницы.

Таблицы и файл базы создаются при первом старте. Данные сохраняются между
перезапусками сервера.

## API

| Метод | Адрес | Действие |
|---|---|---|
| GET | `/api/tasks` | получить все задачи |
| GET | `/api/tasks/:id` | получить задачу |
| POST | `/api/tasks` | создать задачу |
| PUT | `/api/tasks/:id` | обновить задачу |
| DELETE | `/api/tasks/:id` | удалить задачу |
| GET | `/api/notes` | получить все заметки |
| GET | `/api/notes/:id` | получить заметку |
| POST | `/api/notes` | создать заметку |
| PUT | `/api/notes/:id` | обновить заметку |
| DELETE | `/api/notes/:id` | удалить заметку |
| GET | `/api/reports` | получить все отчёты |
| GET | `/api/reports/:id` | получить отчёт |
| POST | `/api/reports` | создать отчёт |
| PUT | `/api/reports/:id` | обновить отчёт |
| DELETE | `/api/reports/:id` | удалить отчёт |

Поля сущностей:

- задача: `text`, `time` (ISO-строка), `done` (0/1);
- заметка: `title`, `text`, `time` (ISO-строка);
- отчёт: `time` (ISO-строка), `mood` (целое число 1–5).

Пример создания задачи:

```bash
curl -X POST http://localhost:3000/api/tasks \
  -H "Content-Type: application/json" \
  -d "{\"text\":\"Сделать проект\",\"time\":\"2026-11-06T10:00:00.000Z\",\"done\":false}"
```

## Как расширять проект

Начните с идеи: какую новую сущность вы хотите добавить (книги, привычки, фильмы,
тренировки). Затем повторите путь, по которому уже устроены задачи.

1. **Таблица.** Добавьте `CREATE TABLE IF NOT EXISTS` в `db.js`.
2. **Модель.** Создайте `models/имя.js` по образцу `models/task.js`: 5 функций CRUD.
3. **Маршрут.** Создайте `routes/имя.js` по образцу `routes/tasks.js`: проверка полей,
   `GET`, `POST`, `PUT`, `DELETE`.
4. **Подключение.** В `index.js` импортируйте новый маршрут и добавьте
   `app.use('/api/имя', имяRouter);`.
5. **Фронтенд-запросы.** В `frontend/assets/js/api.js` добавьте функции
   `get...`, `create...`, `update...`, `delete...`.
6. **Страница.** Скопируйте `example.html` и `example.js`, замените разметку и
   вызовы API. Подключите новый JS-файл в HTML.
7. **Навигация.** Добавьте ссылку на новую страницу в шапку всех HTML-файлов.

В коде уже есть закомментированные примеры «как добавить своё»:

- новая таблица — в `db.js`;
- новая модель — в `models/task.js`;
- новый маршрут — в `routes/tasks.js`;
- новый `fetch`-запрос — в `assets/js/api.js`;
- новая страница — в `example.html` и `example.js`.

Совет для самого первого проекта: **не связывайте сущности через foreign key и JOIN**.
Если нужна связь, сначала обсудите её с преподавателем и храните id как обычное число —
это проще для первого проекта.

## Простая проверка данных

Проверка выполняется на сервере, поэтому её нельзя обойти через инструменты
разработчика:

- обязательные текстовые поля не могут быть пустыми;
- `mood` — целое число от 1 до 5;
- при ошибке сервер отвечает статусом 400 и объектом `{ "error": "..." }`.

Фронтенд дополнительно проверяет поля и показывает сообщение через `alert`.
Не удаляйте серверную проверку: она нужна, даже если форма уже проверяет данные.
